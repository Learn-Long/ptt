# Plan: Fix Time Sorting & Python 3.6.8 Compatibility

## Issues

1. **資訊卡片未按時間排序**：前端 JS 雖已加了日期排序選項，但 JSON 資料本身的預設排序是按使用者名稱字母順序（`hyperlink_spam_detector.py` 第 243-244 行）。需要改為按最新推文時間降序排列，且前端 JS 日期排序的 `parseDatetime` 缺少年份資訊，跨年時會不準確。

2. **Python 3.6.8 兼容性**：`auto_runner.py` 中使用了 `text=True`（Python 3.7+ 才支援），需改為 `universal_newlines=True`。同理 `interactive_runner.py` 也有此問題。f-strings 在 3.6 可用，不需修改。

## Changes

### 1. `hyperlink_spam_detector.py` — 後端排序改為按時間降序

將第 243-244 行：
```python
single_article_violations.sort(key=lambda x: (x['user'], x['article_url']))
cross_article_violations.sort(key=lambda x: x['user'])
```

改為按每筆違規中最新 instance 的 datetime 降序排列：
```python
single_article_violations.sort(key=lambda x: max(inst['datetime'] for inst in x['instances'] if inst['datetime']), reverse=True)
cross_article_violations.sort(key=lambda x: max(inst['datetime'] for inst in x['instances'] if inst['datetime']), reverse=True)
```

這樣 JSON 預設輸出就是最新在前。

### 2. `report.html` — 修正前端日期排序，加入年份

目前 `parseDatetime` 只解析 `MM/DD HH:MM`，跨年資料會排錯。改善方式：
- 在 JSON 輸出中，將 `datetime` 欄位改為包含年份的格式 `YYYY/MM/DD HH:MM`
- 同步修改 `hyperlink_spam_detector.py` 中 `strftime('%m/%d %H:%M')` 為 `strftime('%Y/%m/%d %H:%M')`
- 更新前端 `parseDatetime` 正則表達式以匹配 `YYYY/MM/DD HH:MM`

具體修改：
- `hyperlink_spam_detector.py` 第 276、304、340、364 行的 `strftime('%m/%d %H:%M')` → `strftime('%Y/%m/%d %H:%M')`
- `report.html` 的 `parseDatetime` 更新為匹配 `(\d{4})/(\d+)/(\d+)\s+(\d+):(\d+)`

### 3. `auto_runner.py` — Python 3.6.8 兼容

將第 62 行和第 69 行的 `text=True` → `universal_newlines=True`。

### 4. `interactive_runner.py` — Python 3.6.8 兼容

將第 74 行和第 76 行的 `text=True` → `universal_newlines=True`。

## `web_viewer.py` 不需修改

排序邏輯在 `hyperlink_spam_detector.py`（後端生成 JSON 時的預設順序）和 `report.html`（前端 JS 排序選項），`web_viewer.py` 只負責提供 JSON API 和 HTML 頁面，不涉及排序邏輯。
