# 修復 scraper.py 從 index 4000 開始只抓到 189 篇文章的問題

## 問題診斷結果

### 現象
- `auto_runner.py` 以 `--start-index 4000` 執行 scraper.py
- `output/word/` 只有 189 篇文章，全部集中在 5/10 23:xx ~ 5/11 16:xx
- PTT HatePolitics 最新索引為 **4104**（5/16），index 4000 對應 5/10
- 從 4000 到 4104 共 105 頁 × ~20 篇 = ~2000 篇，但只抓到 189 篇
- `processed_urls.txt` 有 190 個 URL（1 個是 [公告] 被 article_scraper 刪除）

### 根本原因（2 個 bug）

**Bug 1：`scraper.py` 多線程停止邏輯過於激進（主因）**

`scraper.py:main()` (第 262-293 行) 使用多線程爬取索引頁：
- 每批提交 `MAX_THREADS * 2 = 20` 個任務
- 當任何 `process_index()` 返回 `False`（404 或 fetch error），立即設 `stop_requested = True`
- **結果**：一旦某個線程遇到網路錯誤（PTT 常見的 503/超時），整個爬取過程就終止了
- 由於 PTT 經常有間歇性連線問題，scraper 可能在 index 4000-4010 附近就因網路錯誤而停止
- 這解釋了為什麼只有 5/10-5/11 的文章（對應約 index 4000-4010）

**Bug 2：`auto_runner.py` 硬編碼 `--start-index 4000`**

- `auto_runner.py:61` 硬編碼 `--start-index 4000`
- 索引號會隨時間增長，4000 現在對應 5/10，未來會越來越舊
- 應該動態計算起始索引

### 次要問題

- `auto_runner.py` 最後清理 `output/*.json` 但不清理 `output/word/` 和 `processed_urls.txt`
- 如果上次中途失敗，殘留的 `processed_urls.txt` 會導致 article_scraper 跳過已處理的 URL，與實際 output/word 中的檔案不一致

## 修復計畫

### 步驟 1：修改 `scraper.py` — 重構 `main()` 爬取邏輯

**核心改動**：先調用 `get_latest_index()` 確定爬取範圍 `[START_INDEX, latest_index]`，然後在已知範圍內爬取，不再依賴 404 作為停止信號。

```python
def main():
    latest_index = get_latest_index()
    if latest_index is None:
        print("無法取得最新索引，無法繼續。")
        return

    end_index = latest_index  # 包含最新索引
    print(f"爬取範圍: {START_INDEX} ~ {end_index} (共 {end_index - START_INDEX + 1} 頁)")

    with concurrent.futures.ThreadPoolExecutor(max_workers=MAX_THREADS) as executor:
        futures = {}
        current_index = START_INDEX
        failed_indices = []

        while current_index <= end_index:
            # 提交一批任務
            batch_futures = {}
            for _ in range(MAX_THREADS * 2):
                if current_index > end_index:
                    break
                future = executor.submit(process_index, current_index)
                batch_futures[future] = current_index
                current_index += 1

            # 等待批次完成
            for future in concurrent.futures.as_completed(batch_futures):
                idx = batch_futures[future]
                try:
                    result = future.result()
                    if result is False:
                        # 404 或嚴重錯誤，記錄但繼續
                        failed_indices.append(idx)
                        print(f"Index {idx} 失敗，繼續處理其他索引...")
                except Exception as e:
                    print(f"Index {idx} 異常: {e}")
                    failed_indices.append(idx)

            time.sleep(0.2)

        if failed_indices:
            print(f"失敗的索引: {failed_indices}")
        print(f"爬取完成，範圍 {START_INDEX}~{end_index}")
```

**同時修改 `process_index()`**：
- 404 和 fetch error 不再返回 `False`（停止信號），改為返回 `None`（跳過）
- 只有明確的 404 才記錄，網路錯誤也只跳過不停止

### 步驟 2：修改 `auto_runner.py` — 移除硬編碼起始索引

- 刪除 `--start-index 4000` 參數
- 改為不帶參數執行 scraper.py，讓其自動估算近 7 天起始索引
- 在流程開始前清理 `processed_urls.txt` 和 `output/word/`（確保乾淨的全量抓取）

### 步驟 3：修改 `auto_runner.py` — 增加清理邏輯

在 `main()` 開始前增加清理：
```python
def cleanup_old_data():
    # 清理 processed_urls.txt
    if os.path.exists("processed_urls.txt"):
        os.remove("processed_urls.txt")
    # 清理 output/word/
    word_dir = os.path.join("output", "word")
    if os.path.exists(word_dir):
        for f in os.listdir(word_dir):
            os.remove(os.path.join(word_dir, f))
```
