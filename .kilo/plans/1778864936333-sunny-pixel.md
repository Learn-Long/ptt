# Plan: scraper.py 啟動模式 & os.replace 相容性

## 一、scraper.py 啟動模式

### 評估：更簡便的做法

複製成 `auto_scraper.py` 的缺點是**代碼重複**——兩個檔案 99% 相同，未來任何修改都要改兩次。

**更簡便的做法**：給 `scraper.py` 加一個命令列參數 `--start-index N`，跳過所有預估與互動輸入，直接使用指定值。

- `auto_runner.py` 呼叫：`python scraper.py --start-index 4000`
- `interactive_runner.py` 呼叫：`python scraper.py`（行為不變）

只需改一個檔案，零重複。

### 具體修改

#### 1. `scraper.py`

- 加入 `import argparse`（在檔案頂部）
- 新增 `parse_args()` 函數，定義 `--start-index` 參數
- 修改 `get_start_index()` 函數簽名為 `get_start_index(args=None)`：
  - 若 `args` 有 `start_index` 且不為 None，直接使用該值（print 訊息 + save_last_index + return）
  - 否則走現有邏輯（預估 + interactive/cronjob 分支）
- 第 165 行改為 `START_INDEX = get_start_index(parse_args())`
- 加入 `if __name__ == "__main__":` 中呼叫 `main()` 前解析 args

#### 2. `auto_runner.py`

- 第 5-6 行 `scraper.py` 的 config 中 `name` 仍為 `"scraper.py"`
- 第 59-64 行 `run_script` 中 `scraper.py` 的特殊分支，改為：
  ```python
  subprocess.run([sys.executable, "scraper.py", "--start-index", "4000"], ...)
  ```

#### 3. `interactive_runner.py` — 不需修改

呼叫方式仍是 `python scraper.py`，走原有互動邏輯。

## 二、os.replace 相容性

### 評估

用戶回報 `os.replace` 在某些 VM 上寫入 `.tmp` 再覆蓋時會報 `No such file or directory`。分析：

1. **`os.replace` 本身是原子操作**（Python 3.3+），在正常情況下比 `os.remove + os.rename` 更安全
2. **`os.remove + os.rename` 不是原子操作**——存在一個目標檔案不存在的窗口期，且 `os.remove` 在目標檔案不存在時（首次執行）會直接拋 `FileNotFoundError`
3. 真正的問題可能是 Windows 上目標檔案被 `web_viewer.py` 鎖定，或 `.tmp` 檔案路徑問題

### 建議方案

保留 `os.replace` 作為首選（原子、安全），但加入 fallback：若 `os.replace` 失敗，改為直接寫入目標檔案。

```python
json_output_file = 'hyperlink_spam_report.json'
tmp_output_file = json_output_file + '.tmp'
try:
    with open(tmp_output_file, 'w', encoding='utf-8') as jf:
        json.dump(json_report, jf, ensure_ascii=False, indent=2)
    os.replace(tmp_output_file, json_output_file)
except OSError:
    try:
        with open(json_output_file, 'w', encoding='utf-8') as jf:
            json.dump(json_report, jf, ensure_ascii=False, indent=2)
        if os.path.exists(tmp_output_file):
            os.remove(tmp_output_file)
        print("警告：原子寫入失敗，已改用直接寫入模式。")
    except IOError as e2:
        print(f"寫入 JSON 報告失敗: {e2}")
```

這樣既保留了原子寫入的優勢，又在特殊環境下有 fallback 保證可用。

### 具體修改

#### `hyperlink_spam_detector.py` 第 389-393 行

替換原本的 tmp → os.replace 邏輯為上述 try/except 結構。
